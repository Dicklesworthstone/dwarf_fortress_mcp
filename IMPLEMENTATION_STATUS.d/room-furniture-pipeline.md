# Original room recipe through allocation, placement and construction monitoring

`plan_rooms.py allocate --emit room-handoff` now emits the canonical complete
RoomFurnitureHandoff directly from one authenticated, released operations/1.4
inventory capture. The existing room-backed furniture batch and completion CLI
consume it without reconstructing, shrinking or replacing original room intent.
The allocation socket closes before CPU-bound projection; the same deadline and
query authority remain active through allocation, encoding and final disclosure.
A shortage never exports an executable subset. The full legacy diagnostic report
must fit even when only the capsule is exported. Default reports are unchanged.

Twelve new pipeline/export methods passed on Python 3.13.5 using real CLI
subprocesses, private batch/monitor journals and joined fragmented TCP peers.
The maximum case began with an original 32-slot room request and 646 excluded
item IDs, compiled it, read a multipage inventory with 2,000 extra items, exported
the capsule, completed all 32 exact synthetic native placements and reached
shared receipt-linked construction satisfaction. Original input files were
removed after batch creation; every later phase retained the original room plan.
Operations generation 7 and furniture generation 987 remained distinct and bound.
Two default allocation/shortage reports matched the exact previous implementation
(blob d14f134698bacd32ebd394e6f823ec5eccc2666b) byte-for-byte.

All 55 distinct new methods across the handoff, batch, completion and pipeline
suites passed again against the final sources in five split runs: 31 handoff/
batch, 11 completion, 1 maximum completion, 11 pipeline and 1 maximum pipeline.
No tests were skipped in these runs. This supplements 65 exact legacy comparisons
from the individual increments: 33 batch results, 30 completion origins/goals/
digests/results and 2 room allocation reports. These are focused development
results from a byte-verified local subset, not a whole-repository qualification.

Operations fixture payloads are independently assembled. Placement receipts use
production codecs; neither peer is an actual DFHack plugin or live fortress.
No Rust/MCP compilation, DFHack SDK/ABI/game or production admission was executed.
This pipeline does not carry the earlier terrain-monitor completion history or
perform native room assignment. Shared furniture conditions are not proof of
whole-room completion, current usability, continuous stability, terrain safety
or discharged placement effects. The broader bridge beads
`df-dfhack-bridge-plane-c-pic.3/.4/.5` remain open. Native protocols, dependency
