# Native-read-driven room layout (development)

The source now joins the unchanged map/1.5 client to the existing automatic
room solver through one complete observed site mask. It retains original intent,
source bytes and identity, intersects caller constraints, preserves wall shapes,
and exports ordinary canonical RoomPlan/layout/furniture artifacts. One read,
close-before-search, current query authority and a nonrenewing foreground budget
are enforced. Offline replay never claims a current native acquisition.

All 34 focused Python tests pass: 12 site-mask, 11 actual map/solver and 11
CLI/transport tests. Real files, subprocesses and TCP are used; native responses
are explicit fixtures. The complete 1,024-cell/eight-area/32-furnishing case runs
through the actual client. Lost reads, source drift, input and publication
refusals, late revocation, and all export/import forms are covered.

These results do not qualify a DFHack SDK build, live game, Rust/MCP or the full
repository. The site filter cannot certify aquifers, adjacent hazards, support,
native pathfinding, current safety or mining eligibility. No native method,
effect authority, production runner or compatibility admission was widened.
Beads df-dfhack-bridge-plane-c-pic.3/.4/.5 remain in progress.
See docs/OBSERVED_ROOM_LAYOUT.md and architecture/observed_room_layout_v1.json.
