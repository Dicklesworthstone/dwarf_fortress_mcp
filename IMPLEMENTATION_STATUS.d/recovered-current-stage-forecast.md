# Recovered originals in current-stage forecasts

The existing `fortress.query` `forecast_originals` mode can select an exact
recovered original with its default `current_stage` scope. Already-dispatched
excavation, harvesting and production work can share one private simulation with
current-session live originals after durable reopening. A raw action original
does not need to masquerade as a production project or acquire a stock ledger.

Admission retains the exact sealed source, accepted recovery lineage, complete
original step census and authenticated temporal monitors. Historical Verified
steps remain historical; unfinished steps retain their original registration,
absolute deadline, cadence and post-recovery stability. Missing, interrupted,
never-dispatched or inconsistent custody refuses. Present live receipts remain
authoritative and cannot fall back to archival custody.

Selected recovered steps and competing carried peers share action, source,
structural, predicate, polling, tick and wall limits without counting a selected
step twice. Recovered current-stage results preserve null ActionIds and separate
original proof from private predicted proof. No future project stage is prepared
by this scope, and no dispatch handle or canonical observation is restored.
Recovered current-stage selections use response schema
`dfmcp.lab-original-forecast/5`; live-only current-stage `/1` and complete-project
`/2` through `/4` routes retain their contracts. Complete-project forecasting
retains its ledger and continuation requirements.

## Validation scope

Eight new Rust regression functions cover private-model cadence and contention,
durable raw mining without a ledger, mixed live/recovered work, historical
source budgets and exact typed-source witnesses. Existing recovery-refusal
regressions are updated for the supported scope. Independent source review
checks the implementation and fixtures. The current execution environment is unavailable,
so the new Rust code and tests have not been compiled, formatted or executed.
GitHub source and publication readback establish the committed contents only;
they are not runtime qualification. Earlier passing terrain/world/intent tests
do not validate this MCP increment. No native/live admission or release
qualification is claimed.
