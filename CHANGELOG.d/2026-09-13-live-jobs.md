- Added the isolated `dfmcp_jobs_v1_2` DFHack plugin: authenticated Handshake and
  ReadObservation, bounded complete native job rosters, stable ID ordering,
  suspension/repeat flags, job type/reaction, native worker/holder references,
  positions, raw timers, and item-reference/filter counts. No partial roster or
  game mutation is published.
- Added the safe-Rust closed RPC client, bounded canonical payload decoder,
  versioned snapshot projection, generation history, heartbeat/reset handling,
  failed-source fencing, and absolute per-call TCP deadlines.
- Registered `dfmcp-live-jobs-dev-server` and connected the job projection to the
  shared structured entity, aggregate, search, baseline, and condition-watch
  query engines. It preserves the eleven tool names and uses a separate explicit
  development opt-in, token, process-scoped session family, and jobs-only coverage.
- Prevented raw live-ID aliases from being re-encoded into current-process
  session handles. Unbound errors cannot claim complete observed job coverage.
  Local watch management remains available after source failure; authorized
  active watches remain visible across observations.
- Added nineteen Rust regression tests and a 153-byte cross-language golden
  frame. These Rust tests are registered but have not been compiled or executed
  in the editing environment.
- Executed `scripts/test_live_jobs_native_mock.py` with GCC and Clang. Each
  warning-denied C++17 build of the actual plugin source against mock interfaces
  passed 95 checks and matched an independent Python encoder. This is not a
  real DFHack build, generated protobuf/linking test, Rust test, or live campaign.
- Added `docs/LIVE_JOBS.md` with the native external-plugin build path, development
  binary invocation, query examples, exact payload format, and coverage limits.
  Updated `IMPLEMENTATION_STATUS.md` without advancing production admission.

The profile is jobs-only, not a 1.1 superset or a merged citizen/job/inventory
snapshot. Suspension is not a blocker diagnosis, raw timers are not completion
estimates, and disappearing jobs do not prove success. Existing 1.0/1.1 bridge
sources, dependency pins, production runner map, and admitted-tuple registry
remain unchanged. Actual Rust, DFHack, stdio, and live validation are outstanding.
