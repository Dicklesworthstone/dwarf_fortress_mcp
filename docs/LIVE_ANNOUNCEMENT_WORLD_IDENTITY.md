# Announcement window world identity

Bridge generation alone is not a fortress identity. A world can be unloaded and another fortress loaded without relying on process restart. Protocol 1.1 therefore must bind every announcement window to the same canonical fortress identity established by its companion complete observation: world folder, site ID, and derived fortress ID. A continuation is stale if any of those values change.

The native reply may carry the bounded raw world folder and site ID, or the caller may supply an exact observation identity that the reply independently reproduces. The final implementation must not publish an announcement window whose only world fence is bridge generation.
