# Why announcements require a new protocol generation

Adding reports as optional fields to the existing citizen reply would be wire-compatible protobuf but semantically incompatible with the admitted protocol-1.0 capsule. It would change the canonical state domain, method manifest expectations, coverage claims, and evidence campaign without changing the name of the contract.

The announcement slice therefore requires protocol 1.1, a new bridge implementation identity, a fresh native plugin digest, and fresh R1-R5-style evidence. The existing exact protocol-1.0 registry entry remains immutable evidence for the citizen-only source generation. It does not authorize a newer binary merely because old fields still decode.
